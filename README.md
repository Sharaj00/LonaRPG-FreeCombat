# LonaRPG FreeCombat — Beta 0.8.13

Свободное перемещение и бой для **LonaRPG B.0.10.7.5.18**, Windows x86 / RGSS301 (Ruby 1.9.2).

Персонажи движутся свободно без тайловой системы, ближние атаки используют форму штатного навыка, а снаряды летят непрерывно. На глобальной карте остаётся штатное тайловое передвижение.

Основные системы реализованы, проведены автоматические и ограниченные игровые проверки. Полное прохождение до концовки, все классы и сюжетные ветки ещё не проверены; отсутствие ошибок во всей игре не гарантируется.

## Изменения в 0.8.13

- Исправлена диагональная навесная стрельба обычных и элитных скелетов-лучников. Эта стрела использует отдельный штатный механизм; теперь и он ограничен четырьмя направлениями при активном FreeCombat.
- Добавлена опция прохождения игрока и нанятых напарников друг сквозь друга. В `ModScripts/_Mods/FreeCombatPrototype/settings.rb` установите `COMPANION_COLLISION = false` и полностью перезапустите игру. По умолчанию стоит `true`: коллизия включена. Опция действует на картах свободного управления; стены, посторонние NPC и участие напарников в бою сохраняются.
- Diagnostics записывает выбранное состояние коллизии при запуске сессии.

При обновлении сохраняйте свои `FreeCombatPrototype/settings.rb` и `LonaPerformance/settings.rb`. Для этой версии не требуется начинать новую игру с уже установленным набором модов; добавление RolePlay-S к старому персонажу по-прежнему требует новой игры.

## Скачать и установить

Готовые архивы находятся в [Releases](https://github.com/Sharaj00/LonaRPG-FreeCombat/releases).

| Архив | Назначение |
|---|---|
| FreeCombatPrototype-0.8.13.zip | Основной аддон, обязателен |
| FreeCombatDiagnostics-0.2.4.zip | Необязательный журнал ошибок, маркеры и отдельные тестовые режимы |
| LonaPerformance-0.1.15.zip | Необязательные оптимизации геометрии и обработки событий |

1. Закройте игру. Сделайте резервную копию игры и всей папки UserData. Для тестирования используйте отдельную копию игры.
2. Распакуйте нужные ZIP. В каждом находится одна папка аддона (например, `FreeCombatPrototype`). Вручную поместите её в `ModScripts/_Mods/` вашей копии игры. Итоговый путь: `ModScripts/_Mods/FreeCombatPrototype/_ModInfo.json`. Папок `ModScripts` и `_Mods` внутри ZIP нет.
3. Включите выбранные аддоны в штатном менеджере. FreeCombat автоматически настроит порядок поддерживаемого набора; вручную расставлять его не нужно.
4. Полностью перезапустите игру. Если порядок пришлось исправить, появится сообщение и запуск завершится: перезапустите игру ещё один раз. Если порядок уже правильный, дополнительного перезапуска нет. Свободный режим включается при обычной новой игре или загрузке.

Сохранения с FreeCombat требуют включённого FreeCombat: загрузка без него, удаление аддона и откат версии не поддерживаются. Для набора с RolePlay-S нужна **новая игра**; перенос старого персонажа в RolePlay-S не предусмотрен. Файлы `.free-combat.bak` — предыдущие версии перезаписанных сохранений; храните и обычную отдельную резервную копию.

Другие версии игры и произвольные сочетания модов не заявлены как совместимые. Не меняйте Game.ini Title: штатный менеджер читает оттуда версию игры.

## Совместимость и автоматический порядок

Патчи совместимости теперь входят в FreeCombat и подключаются только для включённых, успешно загруженных поддерживаемых модов. Отдельный FreeCombatCompatibility больше не устанавливайте; при обновлении старую папку можно убрать из `_Mods` после резервного копирования. Оставшийся старый патч не должен выполняться повторно.

Встроенные адаптеры исправляют восстановление STA, паузу Temper, взаимодействия Faction Clashes, откат контекста загрузки, уклонение RolePlay-S и журнал добавленных карт. Неподдерживаемые версии или изменённые интерфейсы отмечаются в Diagnostics как причина пропуска.

Настройка учитывает зависимости и правила загрузки. Отключённые моды не включаются; относительный порядок посторонних и отключённых модов сохраняется. Меняются только номера загрузки, предыдущий INI сохраняется в `UserData/GameMods.ini.free-combat-order.bak`. При конфликтующих правилах запуск останавливается с объяснением. Это не делает любые неизвестные моды совместимыми.

## Диагностика и сообщения об ошибках

В основном аддоне нет отладочной панели или тестовых уровней. С включённым Diagnostics:

- F9 показывает/скрывает панель; при запуске она скрыта.
- F11 отмечает проблему без остановки игры.
- F6 из главного меню открывает изолированную арену, F7 — временный тест на карте; F8 возвращает из теста в главное меню. В F6 сброс — F5. Сохранение в тестах заблокировано.

После проблемы нажмите F11 и создайте [Issue](https://github.com/Sharaj00/LonaRPG-FreeCombat/issues): версия игры и аддонов, порядок модов, шаги, ожидаемое и фактическое поведение. Приложите журналы `UserData/FreeCombatDiagnostics/diagnostics.jsonl`, `.jsonl.1`, `.jsonl.2`, если они есть. Сначала просмотрите их: журналы содержат локальные пути и сведения о игровой ситуации.

## Производительность и ограничения

LonaPerformance уменьшает стоимость отдельных расчётов геометрии и диспетчеризации. Библиотека `geometry-x86.dll` — собственный арифметический код, не замена RGSS. Каждую оптимизацию можно отключить в settings.rb. Экспериментальный GC по умолчанию выключен (`GC_BATCH_FRAMES = 0`); оставьте так для обычной Beta.

Перед финальным стабильным релизом остаются полное прохождение, длительные бои, редкие сюжетные состояния, непроверенные сочетания навыков и ручная оценка производительности. Публикация Beta позволяет собрать эти результаты от игроков.

## Исходники и сборка

Собственные исходники трёх актуальных аддонов находятся в `src/`; арифметическое ядро и модули оптимизации — в `src/RGSSPerformance/`. `tools/build_geometry.ps1` собирает DLL с MSVC x86, затем `python tools/build_beta_release.py` формирует архивы и SHA256SUMS. Переданный `-Compiler` должен указывать на x86 cl.exe. Закоммиченные архивы в releases/ — проверенные файлы этой Beta; публикация сверяет их контрольные суммы.
